# Fsp MVP — Final Integration Blockers

This file records the remaining items that must be completed before calling the MVP build-ready.

## 1. Unity project shell and playable starter

Status now:
- `Packages/manifest.json` present with Unity UI 2.0.0.
- `ProjectSettings/ProjectVersion.txt` pins Unity `6000.3.17f1`.
- Starter `Lobby` and `Match` scenes are generated by editor bootstrap.
- Build validator and Android/Windows/iOS build commands are present.
- Android release command now forces IL2CPP + ARM64 + automatic Target SDK and clears Development Build for AAB.
- AAB validation blocks default package identifiers, missing ARM64, non-IL2CPP and Development builds; test APKs are still allowed before the final package ID is chosen.
- `MatchSceneAssembler` creates a playable fallback when final prefabs are missing.
- Fallback local player, 32-slot bot population, safe zone, plane/drop, starter Dune AR-4, ammo/medkit/armor loot, HUD and simple vehicles are wired.
- Placeholder bots are damageable and participate in placement/death logic.
- Starter desktop movement/camera/combat controls exist for smoke testing.
- Sunscar Island starter world includes seven POIs, roads, coast, loot tiers, vehicle distribution, balanced bot spawn anchors and mobile quality/visibility optimization.
- Runtime world/results installers are now restricted to the Match scene so the Lobby does not accidentally build the full island or results UI.
- Static audit fixed duplicate result persistence, runtime scene contamination, invalid LootPickup API usage and several earlier type/reference conflicts.

Still required before a real build can be claimed:
- Open the repository with Unity 6000.3.17f1 and let Unity import/resolve packages.
- Run `Fsp > Project > Recompile and Audit` and fix every actual Unity compiler error.
- Run `Fsp > Project > Validate MVP Build`.
- Let the bootstrap serialize `Assets/Fsp/Scenes/Lobby.unity` and `Assets/Fsp/Scenes/Match.unity`, then commit those generated scenes.
- Perform a Play Mode smoke test of Lobby -> Match -> plane/drop -> combat -> results -> Lobby.
- Produce the first Android test APK and install it on a physical Android device.
- Choose/set the final unique Android application identifier before the release AAB.
- Produce a signed release AAB only after gameplay/network smoke tests pass.

## 4. Final gameplay validation

Required end-to-end checks:
- Lobby -> Solo/Squad queue -> Match ID -> gameplay scene.
- Countdown -> plane -> jump -> parachute -> safe landing.
- Loot claim contention between two players.
- Fire/damage/death/kill feed/placement.
